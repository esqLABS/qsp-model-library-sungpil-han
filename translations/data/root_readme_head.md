## 1. Project Overview

This repository is not a static collection of models designed by a human in one
sitting. It is **a library that grows as an automated AI agent adds one new disease
model every day**. In each session, Claude Code:

1. Picks a disease not yet covered.
2. Draws a **mechanistic map of the disease pathophysiology**, based on the current
   literature and clinical trial data.
3. Writes an **mrgsolve-based ODE model** linking drug PK/PD to disease progression.
4. Builds a **Shiny dashboard** for exploring and comparing parameters.
5. Compiles the **references** underpinning every assumption and parameter.
6. Commits and pushes the deliverables.

The goal is a **reference collection of reproducible, transparent, and
educationally usable QSP models** spanning a wide range of therapeutic areas.

## 2. What is QSP?

**Quantitative Systems Pharmacology (QSP)** combines systems biology with
pharmacokinetics/pharmacodynamics (PK/PD) to express the causal chain running from
**drug to target to pathway to disease to patient** mathematically, usually as
ordinary differential equations (ODEs). It goes beyond a purely statistical
dose-response curve and describes, at the level of mechanism, **why and how**
efficacy and toxicity arise.

A QSP model sets out to answer questions such as:

- If this target is modulated, how do the downstream pathways and the clinical
  biomarkers move?
- Combining drugs with different mechanisms of action, what synergy or antagonism
  appears?
- In which patient subtypes (genotype, severity, comorbidity) does the response
  differ?
- Which dose and dosing interval optimise the balance between efficacy and safety?

## 3. Why QSP Matters in Drug Development

QSP has become a central tool of the **Model-Informed Drug Development (MIDD)**
paradigm that regulators encourage. It contributes across the whole development
cycle:

| Stage | Contribution of QSP |
|------|------------|
| **Target discovery and validation** | Pathway-level simulation to assess in advance how modulating a target affects the disease phenotype, and to predict bypass pathways and resistance mechanisms |
| **Elucidating mechanism of action (MoA)** | Integrating in vitro / in vivo data to quantify the causal structure of the drug effect and to establish a biomarker strategy |
| **Dose and regimen selection** | Mechanism-based prediction of the first-in-human dose, the appropriate regimen, and the therapeutic window, putting phase 1 design on a rational footing |
| **Clinical trial design** | Simulating the response of patient subpopulations to optimise patient selection, stratification, endpoints, and sample size |
| **Translation** | Quantifying species and population differences by extrapolating animal to human, adult to paediatric, and healthy subject to patient |
| **Combination strategy** | Exploring the combined effect (synergy / antagonism) of different targets in virtual patient cohorts |
| **Regulatory communication** | Serving as an evidence package within the FDA and EMA MIDD frameworks, supporting trial waivers and label extensions |

A large share of drug development failures comes from **insufficient efficacy** and
**unanticipated safety problems**. QSP tests hypotheses *in silico* before a
candidate enters the clinic, which **reduces late-stage attrition** and helps stop
programmes that are going to fail sooner and more cheaply (fail fast). This library
provides **reproducible worked examples for teaching and research**, applying that
QSP workflow across a wide range of diseases.

## 4. Four Deliverables per Model

Every disease directory follows the same four-deliverable scheme.

| Deliverable | File | Description |
|--------|------|------|
| 🗺️ **Mechanistic map** | `*_qsp_model.dot` / `.svg` / `.png` | Pathophysiology and drug-action network drawn with Graphviz (100+ nodes, 8+ clusters) |
| ⚙️ **mrgsolve model** | `*_mrgsolve_model.R` | ODE model linking drug PK to disease PD (15+ compartments, 5+ treatment scenarios, notes on calibration against clinical trials) |
| 📊 **Shiny dashboard** | `*_shiny_app.R` | Interactive app for exploring patient profile, PK, PD, clinical endpoints, scenario comparison, and biomarkers (6+ tabs) |
| 📚 **References** | `*_references.md` | 30+ PubMed citations, grouped by section |

Each directory also contains **its own `README.md`** summarising these
deliverables, so the disease overview, key pathways, model specification, and
instructions for running it can be taken in at a glance.

## 5. How It Is Built

- **Automated generation**: Claude Code Routine picks one disease per day, writes the
  four deliverables plus the directory README, then commits and pushes.
- **Duplicate avoidance**: diseases and directories that already exist are skipped, and
  categories are selected in rotation.
- **Quality standards**: the minimum bar is a mechanistic map (100+ nodes / 8+
  clusters), mrgsolve (15+ compartments / 5+ scenarios), Shiny (6+ tabs), and
  references (30+ papers).
- **Naming conventions**: directories are lower-case hyphenated English names; files
  follow `<abbr>_qsp_model.*`, `<abbr>_mrgsolve_model.R`, `<abbr>_shiny_app.R`, and
  `<abbr>_references.md`.

## 6. Technology Stack

| Tool | Purpose |
|------|------|
| **Graphviz** (`dot`) | Rendering the mechanistic map (`.dot` to `.svg`/`.png`) |
| **mrgsolve** (R) | ODE-based PK/PD/QSP simulation |
| **Shiny** (R) | Interactive simulation dashboard |
| **Claude Code Routine** | Daily automated model generation, documentation, and commit |

## 7. Usage

```bash
# 1) Render the mechanistic map (requires Graphviz)
dot -Tsvg <disease>/<abbr>_qsp_model.dot -o <abbr>_qsp_model.svg
dot -Tpng -Gdpi=150 <disease>/<abbr>_qsp_model.dot -o <abbr>_qsp_model.png
```

```r
# 2) Run the mrgsolve model (R)
install.packages(c("mrgsolve", "dplyr", "ggplot2"))
library(mrgsolve)
mod <- mread("<disease>/<abbr>_mrgsolve_model.R")
out <- mrgsim(mod, end = 365)
plot(out)

# 3) Run the Shiny dashboard
install.packages("shiny")
shiny::runApp("<disease>/<abbr>_shiny_app.R")
```
